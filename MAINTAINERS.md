## Becoming a Maintainer

### Path to Committer

To become a committer:

1. **Demonstrate sustained contribution** (3+ months)
2. **Make significant contributions** (5+ merged PRs)
3. **Show understanding of codebase**
4. **Help other contributors**
5. **Follow project guidelines**
6. **Get nominated by a maintainer**
7. **Approved by simple majority vote**

### Path to Maintainer

To become a maintainer:

1. **Be an active committer** (6+ months)
2. **Make substantial contributions** (20+ merged PRs)
3. **Demonstrate leadership**
4. **Participate in community**
5. **Mentor other contributors**
6. **Get nominated by a maintainer**
7. **Approved by 2/3 majority vote**

See [GOVERNANCE.md](GOVERNANCE.md) for detailed nomination process.

## Decision Making

Maintainers make decisions through:

* **Lazy Consensus**: For minor changes (72-hour window)
* **Voting**: For major changes (see GOVERNANCE.md)
* **Discussion**: Open discussion in GitHub
* **Meetings**: Bi-weekly community calls

See [GOVERNANCE.md](GOVERNANCE.md) for details.

## Stepping Down

Maintainers can step down by:

1. Notifying other maintainers
2. Moving to emeritus status
3. Updating this file
4. Transferring responsibilities

Emeritus maintainers are welcome to return with maintainer approval.
